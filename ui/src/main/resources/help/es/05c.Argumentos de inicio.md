# Argumentos de inicio

Al ejecutar Xeres manualmente, puedes proporcionar las siguientes opciones de comando. Esto es solo para un uso avanzado y normalmente no es necesario.

- `--no-gui`: inicia sin interfaz. Se puede usar para ejecutar Xeres en modo sin interfaz gráfica (headless). Usa otra instancia con `--remote-connect` para conectarte a ella.
- `--iconified`: inicia minimizado en la bandeja. Esto es útil para el inicio automático.
- `--data-dir=<path>`: especifica el directorio de datos. Es donde Xeres almacena todos sus archivos de usuario. Si quieres ejecutar varias instancias, cada una necesita tener un directorio de datos diferente.
- `--control-address=<host>`: especifica la dirección a la que vincularse para el acceso remoto entrante (por defecto solo localhost).
- `--control-port=<port>`: especifica el puerto de control para el acceso remoto. Este es el puerto al que se conectará la interfaz. Si quieres ejecutar varias instancias, cada una necesita tener un puerto de control diferente, pero Xeres intentará encontrar un puerto libre automáticamente (a partir de 6232), por lo
  que rara vez se necesita este argumento.
- `--no-control-password`: no protejas la dirección de control con una contraseña. La contraseña se genera automáticamente en la primera ejecución y es visible en la configuración. Se puede cambiar o desactivar.
- `--server-address=<host>`: especifica una dirección local a la que vincularse (si no se especifica, se vincula a todas las interfaces).
- `--server-port=<port>`: especifica el puerto local al que vincularse para las conexiones entrantes. Por defecto, Xeres elige un puerto aleatorio y lo usa para siempre en la misma instancia.
- `--fast-shutdown`: ignora el procedimiento de apagado correcto. Es útil sobre todo para pruebas, cuando necesitas iniciar/detener rápidamente instancias de Xeres. No es necesario para el uso normal.
- `--server-only`: solo acepta conexiones entrantes, no realiza conexiones salientes. Útil sobre todo para servidores de chat.
- `--remote-connect:<host>[:<port>]`: inicia como cliente de interfaz y se conecta al nodo especificado. También puedes hacerlo entre máquinas en una LAN. Ten en cuenta que la conexión no está cifrada. Usa túneles SSH si quieres superar esa limitación.
- `--remote-password=<password>`: contraseña que se usará al conectarse de forma remota
- `--version`: imprime la versión del software
- `--help`: imprime el mensaje de ayuda
