# Arguments de démarrage

Lorsque vous exécutez Xeres manuellement, vous pouvez fournir les options de commande suivantes. Ceci est uniquement pour une utilisation avancée et n'est normalement pas nécessaire.

- `--no-gui` : démarrez sans interface. Peut être utilisé pour exécuter Xeres en mode headless. Utilisez une autre instance avec `--remote-connect` pour vous y connecter.
- `--iconified` : démarrez réduit dans le bac à système. Utile pour le démarrage automatique.
- `--data-dir=<path>` : spécifiez le répertoire de données. C'est là que Xeres stocke tous ses fichiers utilisateur. Si vous voulez exécuter plusieurs instances, chacune doit avoir un répertoire de données différent.
- `--control-address=<host>` : spécifiez l'adresse à laquelle se lier pour l'accès distant entrant (par défaut, uniquement localhost).
- `--control-port=<port>` : spécifiez le port de contrôle pour l'accès distant. C'est le port auquel l'interface se connectera. Si vous voulez exécuter plusieurs instances, chacune doit avoir un port de contrôle différent, mais Xeres essaiera de trouver automatiquement un emplacement libre (à partir de 6232), cet
  argument est donc rarement nécessaire.
- `--no-control-password` : ne protégez pas l'adresse de contrôle avec un mot de passe. Le mot de passe est auto-généré au premier lancement et est visible dans les paramètres. Il peut être modifié ou désactivé.
- `--server-address=<host>` : spécifiez une adresse locale à laquelle se lier (si non spécifiée, se lie à toutes les interfaces).
- `--server-port=<port>` : spécifiez le port local auquel se lier pour les connexions entrantes. Par défaut, Xeres choisit un port aléatoire et l'utilise pour toujours pour la même instance.
- `--fast-shutdown` : ignore la procédure d'arrêt appropriée. Ceci est surtout utile pour les tests lorsque vous devez rapidement lancer/arrêter des instances Xeres. Pas nécessaire pour une utilisation normale.
- `--server-only` : accepte uniquement les connexions entrantes, ne fait pas de connexions sortantes. Surtout utile pour les serveurs de chat.
- `--remote-connect:<host>[:<port>]` : démarre comme un client d'interface et se connecte au nœud spécifié. Vous pouvez également faire cela entre machines sur un LAN. Attention, la connexion n'est pas chiffrée. Utilisez des tunnels SSH pour surmonter cette limitation.
- `--remote-password=<password>` : mot de passe à utiliser lors d'une connexion distante
- `--version` : affiche la version du logiciel
- `--help` : affiche le message d'aide
